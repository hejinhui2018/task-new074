# StateVault · 本地状态迁移验收台

用 React + TypeScript + Vite 从零实现的「浏览器本地状态结构升级」验收台。
模拟一个复杂工作台从 **v0（2019 老版扁平结构）跨多版升到 v5** 的全过程，
专门验收：迁移中途失败不留半新半旧数据、刷新后继续不重复应用、损坏数据隔离不覆盖原快照。

## 启动

```bash
npm install
npm run dev       # 开发
npm run build     # 类型检查 + 生产构建
npm run selftest  # 引擎自测（38 项，node + 内存存储，无浏览器）
```

## 版本模型

| 版本 | 结构要点 |
| --- | --- |
| v0 | `user / todos:string[] / theme / notify`，无 version 字段 |
| v1 | todos 结构化为 `tasks:{id,title,done}[]` |
| v2 | 用户与外观收拢为 `profile` |
| v3 | 设置独立成 `settings`，任务补 `createdAt` |
| v4 | `done` 布尔 → `status` 状态机 + `tags` |
| v5 | `workbench` 信封，tasks 数组 → 字典 + `order` 顺序表 |

每个迁移只能从相邻版本出发（`src/engine/migrations.ts`），包含：

- **变更定义** `up`：在输入的深拷贝上做结构转换；
- **校验规则** `validate`：提交前对产物做结构校验（id 唯一、字段类型、字典与顺序表一致等）；
- 页面上每步展示 **输入版本 / 变更 / 校验规则 / 失败影响**。

## 核心保证（`src/engine/engine.ts`）

1. **原子提交**：每步 = `前置快照（深拷贝）→ 副本上 transform → validate → 一次性替换 live`。
   任一环失败，live 保持上一版本，不会出现半新半旧。
2. **损坏隔离**：transform 抛错或校验失败的半成品进入 `quarantine`，
   并附原因 / 阶段 / 迁移 id；localStorage 原文损坏时，原始字符串完整隔离，**绝不覆盖**。
3. **幂等闸门**：版本号是唯一真相。`live.version !== migration.from` 时该步跳过，
   同一迁移重跑任意次都不会重复应用。
4. **中断恢复**：live、计划（`pending.nextIndex`）、快照、日志随整封写入 localStorage；
   迁移中途刷新 / 崩溃，重开后报告「已提交 N 步」，可从第 N+1 步继续或放弃。
5. **降级读取**：读到更高版本（演示用 v6）存档时进入只读模式，原样保留，拒绝迁移。
6. **撤销 / 重做**：每次提交前后状态入历史栈，撤销直接恢复快照而非重跑迁移；新提交清空重做栈。

## 界面能力

- 单步 / 自动运行（900ms/步）/ 暂停 / 继续 / 终止计划
- 故障注入：指定步骤生成「损坏半成品」（被校验拦截）或让 transform 抛异常；可运行中暂停后武装
- 撤销 / 重做 / 从任意回滚快照恢复
- 模拟刷新恢复；重置到 v0–v5 任一版本
- 一键验收场景：跨多版、中途失败、抛异常、重复运行幂等、中途刷新、存储损坏、降级读取、撤销重做
- live JSON、回滚快照、隔离区（含半成品与损坏原文）、撤销重做栈、事件日志检视

## 验证

- `npm run selftest`：38 项引擎断言（跨多版、失败回滚隔离、幂等、中断续跑、存储损坏、未来版本只读）。
- 另对生产包做过 jsdom 端到端冒烟（24 项真实 DOM 交互），脚本不在仓库内。
